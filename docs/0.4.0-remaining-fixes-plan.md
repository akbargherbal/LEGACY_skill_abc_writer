## 0. Goal in one line

> 0.3.0 turned the three metrics that were **outside** the 177-track corpus into
> hard failures. 0.4.0 must make the **inside-the-corpus** expert findings
> (breath, tessitura, rhythm, ornament translation) enforceable **when the plan
> declares them**, and must stop the skill from teaching the mediocre run's
> plan and high-tessitura example as the shape to copy.

The hard `sanity` gate stays corpus-calibrated. The new checks are **brief
targets**: declared by the plan, enforced by a new `strict_shape` mode, and
reported as warnings otherwise. This preserves the 95% rule for hard gates and
makes the expert's acceptance a real, opt-in acceptance test.

### What 0.3.0 already fixed (do not redo)

- The 0.2.0 rule "the tonic at each phrase end" → final tonic + resting tones.
- Three shape sanity guards: unbroken ≤ 23 s, repeated ≥ 20%, endings ≥ 3.
- Maqam spelling table and maqam-relative chromatic.
- Error→fix table, revision protocol, style targets instead of sanity ceilings.
- The old mediocre score: **FAIL 3 hard** under 0.3.0.

### What remains open

| Finding | 0.3.0 state | Plan |
|---|---|---|
| **F1** breath / 5-bar phrases | Prose fixed; hard only at 23 s; 10 s is style; no per-hemistich check | **W2 + W5** |
| **F2** uniform eighths / no text-driven rhythm | 0.65 style / 0.85 hard; `syllabify.py` says "no scansion" | **W2 + W5** |
| **F3** melodic shape | Mechanical signatures fixed; stepwise not gated (correct); verse/chorus only max-note | **W3** (chorus median) |

## 1. Non-negotiable constraints

1. **Hard gates stay corpus-calibrated.** The nine sanity guards and the 175/177
   joint pass do not change. New targets are `style` or `strict_shape`.
2. **Backward compatibility.** A 0.2.0/0.3.0 plan without `strict_shape` keeps
   the 0.3.0 behaviour. No old plan starts failing because a new field is
   absent.
3. **No new number without provenance.** Every added target gets `class`,
   `basis`, `n`, `pass`, `used_in` in `references/numbers.md` and
   `scripts/calibration.json`.
4. **No dialect changes.** No `w:` lines, no quarter tones, no third voice, no
   contract changes in `abc_tools.py`.
5. **No listening claim.** These are score-shape targets, not beauty.
6. **The example is a syntax fixture, not a song to copy.** Its register,
   density, and proportions are not a model.
7. **A quality target cannot be discharged by an arrangement deviation.**
   "My brief asked for a high chorus" is not a reason to miss the breath or
   tessitura target; the model fixes the music or asks the user.

### W5 — Per-hemistich phrase plan and text-driven rhythm (F1/F2)

**Problem.** The input lyrics are already one hemistich per line. The skill says
"one line = one phrase", but there is no artifact that records the per-line bar
range and pause, and the checker cannot verify it. `syllabify.py` explicitly
does "no scansion". The old score chained two lines into 5-bar phrases.

#### W5.1 — Phrase sidecar and checker (0.4.0)

- [ ] `syllabify.py --json` adds (the existing `lines` count stays):
  ```json
  "phrase_plan": {
    "body_bars": 58,
    "lines": [
      {"line": 1, "section": "verse 1", "syllables": 14, "bars": 2,
       "body_bar_start": 1, "body_bar_end": 2, "pause_after_s": 0.5}
    ]
  }
  ```
  The `bars` are the per-line budget from the existing `pace` calculation.
- [ ] Add `syllabify.py --phrases phrases.json` (or make `--json` include the
  lines). The model copies the lines into `phrases.json` and sets the absolute
  `bar_start`/`bar_end` after the section layout:
  ```json
  {"tempo": 74, "unit": "1/16",
   "lines": [{"line": 1, "section": "verse 1", "syllables": 14,
              "bar_start": 10, "bar_end": 11, "pause_after_s": 1.62}]}
  ```
- [ ] `checker.py --phrases phrases.json`:
  - for each line, collect the vocal notes in `[bar_start, bar_end]`;
  - require at least one note;
  - require the last note to end at least `pause_after_s` before the next
    line's first note (or the next section's start);
  - require the phrase span ≤ `max_unbroken_seconds`;
  - require ordered, non-overlapping ranges; every line accounted for;
  - report `phrases_checked`, `phrase_violations`, and the per-line spans.
  - `strict_shape` makes a miss a FAIL; otherwise WARN.
- [ ] `SKILL.md` §3.3: "Before writing notes, copy the line table; one line is
  one phrase; put the rest at the line end. If a line is longer than 10 s,
  split it at the caesura." Link to the sidecar command.
- [ ] `SKILL.md` §3.5: the check command gains `--phrases phrases.json` when the
  sidecar exists.
- [ ] `schemas/phrases.schema.json` for the sidecar.
- [ ] Tests:
  - a 5-bar phrase with no line-end rest fails;
  - a correctly separated 2-line phrase passes;
  - a sidecar missing a line fails;
  - `strict_shape` off leaves it a WARN.
- [ ] `docs/agent-eval-protocol.md` T17 updated to require the sidecar and the

**Acceptance:** the old 78-bar lyric layout can no longer pass with one breath

## 5. Acceptance criteria for 0.4.0

1. **Hard gate unchanged:** 177/177 parse, 175/177 hard (98.9%); no new sanity
   guard is added.
2. **Old score still fails:** the 34.05 s / 6.1% / 2-ending score fails the
   three hard shape guards with or without `strict_shape`.
3. **Minimally repaired score fails `strict_shape`:** a 20 s / 72% / 82.1%
   score with `strict_shape: true` fails the declared breath, duration,
   tessitura, and chorus targets.
4. **Example passes strict:** `--strict-style` + `strict_shape` on the bundled
   example: 0 FAIL, 0 WARN.
5. **Example is corpus-shaped:** register mean/top, tessitura, Ins active, and
   silence are within the documented P5–P95 (or the target range for silence);
   no metric is P100.
6. **Template is not case-specific:** `SKILL.md` §3.2 contains no `78`, `361`,
   or the four run bar ranges; T22 on a different lyric/maqam/tempo produces
   its own numbers.
7. **Phrase sidecar:** a missing line-end pause fails under `strict_shape`; a
   correct layout passes; every line has a bar range.
8. **Backward compatibility:** a 0.2.0/0.3.0 plan without `strict_shape` parses
   and behaves as before.
9. **Docs/registry:** every new number has class/basis/n/pass/used_in; the
   release notes name the evidence and the rollback.
10. **Two-agent eval:** T21 passes with 0 WARN; T22 shows no leakage; T17 shows
    per-line pauses; no quality regression.

## 6. Risks and mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Overfitting the 177 | New targets punish good scores | Keep hard gates at 95%; new targets are `style`/`strict_shape`; register the target's pass rate |
| `strict_shape` becomes a hidden hard gate | Old plans break | Default false; old plans unchanged; release notes |
| The model ignores `strict_shape` | The old WARN passes | Template sets true; T21; docs; `--strict-style` final pass |
| Example rewrite changes the dialect | Selftest/tests fail | Keep the 16-bar shape; change register/Ins/silence only; run `make test`/`selftest` |
| Phrase sidecar bloats tokens | Cost regression | Separate `phrases.json`; do not put 26 lines in `plan.json`; only pass when present |
| Round-trip mismatch between `syllabify` and the score | False puzzle | Sidecar ranges are recommendations; the model sets absolute bars; checker compares the score |
| Tessitura target is culturally wrong | High voices punished | 0.80 style; the plan declares it; the corpus distribution is documented; no sanity gate |
| Chorus 5 warns a minority | Noise | Style only; default 4; 5 in the release template; P95 7 is documented |
| Contract pins drift | CI fails | Re-pin after final edit; `contract --strict`; clean-room |
| The example is a showcase, not a model | Models copy an outlier | Strict pass + percentile check; label as syntax fixture |
