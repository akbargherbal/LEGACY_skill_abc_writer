## 1. What changed

### 1.1 One contract

- `SKILL.md` §3: `syllabify → plan → core (8–16) → score → seed →
  seed_sheet/notes`. `seed_sheet.md` is written **after** `score.abc`; the
  82-bar frame is not a precondition for the core.
- `task.md` (session 09): one page. It carries the inputs, the three quality
  levers, the 52,460 budget, acceptance and stop rules. It points to
  `SKILL.md §3`; it does not repeat the 10-line rules, the checker policy or
  the tool commands.
- `SKILL.md` §3.5: one checker policy. After the first score; each later run
  follows a named fix; stop after a pass; a global sanity failure allows one
  full rewrite + one verification; contract errors after that are named fixes;
  max 4. No run after a pass.
- Register: `mean 70, top 80, max_top 84` (the example plan). The sanity band
  `74 ± 5` stays in `checker.py`/`calibration.json`/the reference; 74 is not the
  composing default. `references/reference.md` now says 74 is for a high
  tenor/female lead.
- The `checker.py` plan-register fallback changed from 74 to 70. No gate logic
  or `calibration.json` change.

### 1.2 One toolchain

- `scripts/verify_package.py` (new): parses the score and the three-voice seed,
  strips chords, compares Vocal/Ins bar by bar, checks Drums 82 bars and the
  silent tail, core prefix, the 10-line sheet/notes, the plan's
  `strict_shape`/register, and `report.json`. It writes `verify.json`; it is
  structural, not a taste gate.
- `scripts/craft.py` (new): report-only tune mirror (rhythm variety, contour,
  cadence ladder, unique bars, end-long, tessitura). It wraps the tested
  `_craft_calibrate.py` / `_craft_measure.py` copies. It does not enter
  `checker.py` or `calibration.json`.
- `scripts/selftest.sh`: runs `verify_package` and `craft` on the example, plus
  a short-bar negative.
- `templates/STATE.md` (new): Done / Verified / Decisions / Next. The agent
  copies it and updates it after each artifact/check; after a compaction it
  reads it first.
- `SKILL.md` tool map: adds `verify_package.py` and `craft.py`; documents
  `abc_tools.py` as the score parser CLI (`inspect/strip-chords/compare`).
  The "only verifier" and "count by eye" lines are gone.
- `CHANGELOG.md`: 0.6.0 entry.

## 2. Deviations from the plan (declared)

1. **`craft.py` is score-only.** The old `measure_rhythm.py` seed parser could
   not read the interleaved `V: Drums` blocks (it broke at the first `V: Vocal`
   after the header), and the drum interaction is not one of the three quality
   levers. The seed is structural in `verify_package.py`; the melody is in
   `craft.py`. This is a scope reduction, not a gate.
2. **The contract version stays 0.4.0.** The package version is 0.6.0; the
   gates and `calibration.json` are unchanged. The pin test asserts 0.4.0.
3. **The sanity `74 ± 5` stays.** The plan default is 70; the sanity band and
   the corpus 74 tables are validity/reference, not the composing target.
4. **`checker.py` changed two non-gate lines:** the help text and the
   plan-register fallback 74→70. The gate logic is untouched; the OSTRIS pin is
   updated to match.
5. **The session 09 package is prepared, not run.** The user will test it on a
   new VM; the next session evaluates the result.
